# نظام إدارة طلبات متجر إلكتروني — تحليل المتطلبات

الطلب الأصلي (من المشهد 04):
> تصرف كمهندس برمجيات Full-Stack. أريد بناء نظام لإدارة طلبات متجر إلكتروني، يحتوي على تسجيل دخول، ولوحة تحكم، وتتبع حالة الطلب، وإدارة العملاء. ابدأ بتحليل المتطلبات، ثم اقترح بنية تقنية مناسبة، ونفذ المشروع على مراحل، واكتب اختبارات للتحقق من الوظائف.

## المتطلبات الوظيفية
1. تسجيل دخول الموظفين بكلمة مرور مخزنة كـ hash مملّح (PBKDF2)، وجلسات بملفات تعريف ارتباط HttpOnly.
2. لوحة تحكم: عدد الطلبات، الطلبات حسب الحالة، الإيراد، أحدث الطلبات.
3. تتبع حالة الطلب عبر آلة حالات صريحة:
   `جديد → قيد التجهيز → تم الشحن → تم التسليم`، ويمكن `الإلغاء` قبل الشحن فقط.
4. إدارة العملاء: إضافة عميل، عرض العملاء وعدد طلباتهم.
5. سجل زمني لكل تغيير في حالة الطلب.

## البنية التقنية المقترحة
- Python 3 (مكتبة قياسية فقط) + SQLite → بدون اعتماديات خارجية، يعمل بأمر واحد.
- `app/store.py`: طبقة البيانات وقواعد العمل (قابلة للاختبار بمعزل عن HTTP).
- `app/auth.py`: تجزئة كلمات المرور والجلسات.
- `app/server.py`: خادم HTTP وواجهات HTML عربية (RTL).
- `tests/`: اختبارات unittest لقواعد العمل والمصادقة والخادم.

## مراحل التنفيذ
- المرحلة 1: النموذج والبيانات + اختبارات.
- المرحلة 2: المصادقة + اختبارات.
- المرحلة 3: الواجهات ولوحة التحكم + اختبار تكامل HTTP.
- المرحلة 4 (تعديل على مشروع قائم): منع الانتقالات غير المسموحة بين الحالات وإضافة السجل الزمني — مع اختبار يفشل أولاً ثم ينجح.
